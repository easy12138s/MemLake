## 数据备份与恢复

备份覆盖关系表、AGE 图数据、pgvector 向量与 ag_catalog 元数据（`pg_dump -F c` 自定义格式）。

```bash
cd deploy
./backup.sh                        # 备份到 backups/（默认保留 30 天）
./backup.sh /path/to/dir           # 指定目录
RETENTION_DAYS=14 ./backup.sh      # 自定义保留期

./restore.sh                       # 恢复最新备份（停 mem-lake → 重建库 → 恢复 → 重启）
./restore.sh backups/memlake_20260808.dump
```

定时备份（每日 2:00，保留 30 天）：

```bash
sudo cp deploy/memlake-backup.cron /etc/cron.d/memlake-backup
sudo chmod 644 /etc/cron.d/memlake-backup
```

误操作防护：`docker compose down` 不带 `-v` 不删数据卷；恢复流程见 [DEPLOYMENT.md](../../DEPLOYMENT.md) 数据备份章节。

## 监控

### /metrics 端点

| 端点 | 内容 |
|------|------|
| `http://<host>:8000/metrics` | MCP 网关指标 |
| `http://<host>:8001/metrics` | Embedding 服务指标（embed/rerank 调用数、耗时、输入规模） |

内网 Prometheus 直接抓取；公网暴露需自行加防护层。

### 核心指标族（`src/mem_lake/observability/metrics.py`）

| 指标 | 类型 | 含义 |
|------|------|------|
| `memlake_mcp_tool_calls_total{tool,status}` | Counter | 工具调用量与成功/失败 |
| `memlake_mcp_tool_duration_seconds{tool}` | Histogram | 工具耗时 |
| `memlake_approval_batches_total{status}` | Counter | 审批批次终态（含宽松模式 approved） |
| `memlake_search_engine_duration_seconds{engine}` | Histogram | 三引擎（vector/fulltext/graph）各自耗时 |
| `memlake_embedding_calls_total{op}` / `memlake_embedding_duration_seconds{op}` | Counter/Histogram | embedding/rerank 调用与耗时 |
| `memlake_rerank_fallback_total` | Counter | 精排降级回退 RRF 次数 |

## 日志

结构化日志（structlog），`OBS_LOG_FORMAT=json` 输出单行 JSON（生产推荐），每条工具调用贯通 `request_id / operation_id / actor / project_id` 上下文。

```bash
docker compose logs -f mem-lake           # 实时
docker compose logs --tail 100 mem-lake   # 最近 100 行
```

中间件按调用输出 `TOOL_CALL actor=... tool=... status=... duration=...ms op_id=...` 单行摘要，可用 grep/jq 快速过滤。

## 数据库状态速查

```bash
# 节点分布
docker exec deploy-postgres-1 psql -U memlake -d memlake -c \
  "SELECT status, count(*) FROM knowledge_node GROUP BY status;"

# 待审批批次
docker exec deploy-postgres-1 psql -U memlake -d memlake -c \
  "SELECT count(*) FROM approval_batch WHERE status='pending_review';"

# Access Key 状态
docker exec deploy-postgres-1 psql -U memlake -d memlake -c \
  "SELECT role, status, count(*) FROM access_key GROUP BY role, status;"
```

## 版本更新

```bash
git pull
docker compose up -d --build
```

Schema 变更自动处理：表结构由应用启动 `create_tables()` 幂等补齐（含 `ADD COLUMN IF NOT EXISTS`、`DROP NOT NULL` 迁移）；tsvector 触发器由 `init_knowledge_schema()` 幂等重建。单容器重启即可：`docker compose up -d --build --no-deps mem-lake`。

## 故障排查索引

| 症状 | 入口 |
|------|------|
| 容器启动失败 | `docker compose ps` + 各容器 logs；postgres 首建 10-15 分钟属正常；embedding 健康检查失败先查模型挂载 |
| 认证失败 | 请求头带 `X-MCP-Key`；查 Key 状态 active；明文丢失只能重新创建 |
| 连接池耗尽（`QueuePool limit reached`） | 调大 `DATABASE_POOL_SIZE` / `DATABASE_MAX_OVERFLOW` 重启 |
| 数据误删 | `./restore.sh --yes backups/<file>.dump` |

完整排查步骤见 [DEPLOYMENT.md](../../DEPLOYMENT.md) 故障排查章节。
