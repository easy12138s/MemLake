# Mem Lake Wiki

**Mem Lake 是面向软件研发团队的多智能体协作记忆基础设施**：团队里每个人（PM、开发、管理者）的 AI 通过同一份 MCP 服务共享知识记忆，工作产出自动沉淀为知识图谱，每个 Agent 既是贡献者也是受益者。

```bash
cp .env.example .env
docker compose -f deploy/docker-compose.yml up -d --build
```

两步部署，三个容器（PostgreSQL / Embedding / MCP 网关），接入即用。

## 30 秒了解 Mem Lake

**场景一：需求上下文只在会话里。**
PM 的 AI 帮忙梳理了 PRD、分析了影响范围、检测了冲突——这些上下文只留在 PM 自己的会话里。开发接手时，AI 对新需求一无所知。

**场景二：模块知识跟着人走。**
老张写的模块只有老张的 AI 知道设计意图、方案取舍、踩过的坑。老张休假，小李接手只能翻代码猜或打电话。

**场景三：传统知识库文档无关联。**
Confluence 上一篇篇独立文档，需求是需求、方案是方案，AI 不知道它们之间的关系，也不知道去哪找当前任务的上下文。

Mem Lake 的答案：**不需要专人维护知识库，也不需要单独部署一个 Agent**。团队里每个人本来就在用 AI 干活，这些 AI 的产出通过 MCP 工具自动写入共享图谱（需求、代码、方案、设计意图、决策、踩坑及其关系），之后任何人的 AI 都能检索消费。分布式地建，集中式地用。
