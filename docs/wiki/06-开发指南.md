## 代码结构

模块职责与依赖方向（gateway → approval/search → knowledge → db 单向，approval 与 search 严格隔离避免循环依赖）见 [架构与实现 §源码结构](02-架构与实现.md#源码结构)。

各模块关键文件：

| 模块 | 关键文件 | 内容 |
|------|---------|------|
| gateway | `server.py` `middleware.py` `tools/{write,review,manage,search,query}_tools.py` `background_tasks.py` | FastMCP 实例与 lifespan、四中间件、24 工具按类型分组注册、异步重嵌 worker |
| approval | `service.py` `conflict.py` `models.py` | 批次状态机、事务共写、幂等、三层冲突检测 |
| knowledge | `repository.py` `age_store.py` `schema.py` `models.py` `embed.py` | 节点 CRUD、AGE Cypher 封装、schema 校验、embed 文本构造 |
| search | `vector.py` `fulltext.py` `graph.py` `fusion.py` `filters.py` `tag_expansion.py` | 三引擎与 RRF 融合、统一过滤契约、标签语义扩展 |
| auth | `service.py` `rbac.py` | Key CRUD/认证/rotate/scope、角色工具集常量 |
| observability | `metrics.py` `logging.py` | Prometheus 指标定义、structlog 配置 |
| db | `session.py` `init.py` | 共享连接池/会话工厂、幂等建表迁移 |
| cli | `__init__.py` `__main__.py` | memlake-bootstrap-admin 引导命令入口 |

## 本地开发环境

```bash
# 1. 起依赖容器（postgres/embedding），本地直连
cd deploy && docker compose up -d postgres embedding

# 2. conda 环境 + localhost 连接跑测试
conda activate memlake
export DATABASE_URL="postgresql+psycopg_async://memlake:memlake@localhost:5432/memlake"
export EMBEDDING_HOST=localhost
```

Windows 本地跑测试用 PowerShell `$env:DATABASE_URL=...`；项目自带 WindowsSelectorEventLoopPolicy 处理 psycopg3 事件循环兼容（`tests/conftest.py`）。

## 测试体系（三层）

| 层 | 目录 | 定位 | 运行 |
|----|------|------|------|
| 单元 | `tests/unit/`（25 个测试文件） | mock 依赖直调函数；RBAC/过滤编译/融合/状态机/中间件等 | `pytest tests/unit -q` |
| 集成 | `tests/integration/`（14 文件） | 真实 PG+AGE；service 层端到端 + 内存 MCP 客户端走完整中间件链 | `pytest tests/integration -q` |
| E2E | `tests/e2e/test_mcp_e2e.py` + `tests/integration/test_e2e_roles_collaboration.py` | 前者真实 HTTP 手动脚本（需 admin key）；后者内存客户端三角色协作自动化（pytest 可入 CI） | 脚本 `python tests/e2e/test_mcp_e2e.py --admin-key <key>`；自动化 `pytest tests/integration/test_e2e_roles_collaboration.py -q` |

### conftest 关键 fixtures（`tests/conftest.py`）

- `db_session`：事务回滚隔离——测试内写入结束 rollback，不污染共享 DB；
- `init_tables`：session 级幂等建表（DDL 与 DML 隔离）；
- `real_embedding_client`：连真实 embedding 容器，不可达自动 `pytest.skip`；
- `mock_embedding_client`：固定 1024 维向量，流程验证用；
- 内存 MCP 客户端范式：`fastmcp.Client(create_mcp_server())` + monkeypatch 认证函数注入角色（参照 `test_gateway_tools_manage.py` 与 `test_e2e_roles_collaboration.py` 的 `_make_role_app`）。同角色多次调用需用**确定性 key_id**（幂等键依赖 submitted_by）。

## 扩展改造路径

### 新增 MCP 工具

1. 在 `src/mem_lake/gateway/tools/` 对应分组文件注册工具（`@mcp.tool` + 读写 annotations），工具层只做参数解析与事务边界；
2. `src/mem_lake/auth/rbac.py` 把工具名加入对应角色 frozenset（admin 自动获得全量并集）；
3. 同步 `src/mem_lake/skills/{role}/SKILL.md` 用法说明与版本号；
4. 补测试：unit（参数构造/校验）+ integration（service 端到端）。

### 新增表列（存量库兼容）

遵循 `db/init.py` 既有模式：ORM 定义 + `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`（或 `DROP NOT NULL`）幂等迁移，启动期自动补齐，无需手动 SQL。

### 更换 Embedding 模型

改 `.env` 的 `EMBEDDING_MODEL_PATH`/`EMBEDDING_DIMENSION` → 用 `scripts/calibrate_conflict_threshold.py` 重新标定冲突阈值 → admin 调 `reindex_project_vectors` 全量重嵌。
