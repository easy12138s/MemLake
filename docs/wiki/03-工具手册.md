# 工具手册

> 上一步：[架构与实现](02-架构与实现.md) · 下一步：[部署指南](04-部署指南.md)

31 个 MCP 工具按角色分配。角色由 Access Key 决定，Agent 接入后 `tools/list` 只能看到自己角色的工具。详细参数以仓库 `src/mem_lake/skills/{role}/`（GitHub raw URL 分发）的角色 SKILL 文档为准，本页给全景与工作流。

## PM 工具（9 个）

| 工具 | 读写 | 职责 |
|------|:---:|------|
| `publish_requirement` | 写 | 发布需求（必带 system_id，project_id 可选=悬浮）；支持 related 关联、operation_id 幂等 |
| `update_requirement_relations` | 写 | 批量维护需求间关系边（conflicts_with/duplicates/relates_to/supersedes 等） |
| `update_node` | 写 | 修改已入库节点内容（走审批，版本递增） |
| `search_similar_requirements` | 读 | 向量+全文融合检索相似需求；按 system（含悬浮）或 project 隔离；tags AND/OR 与语义扩展 |
| `check_requirement_conflicts` | 读 | 对需求节点做向量相似度冲突预检（发布前排查，排除自身，阈值与审批流同源） |
| `analyze_impact_scope` | 读 | 需求影响面分析：需求→实现代码→方案→设计意图→踩坑逐层展开；含 references/described_by 挂载资产（pitfalls 段） |
| `get_requirement_context` | 读 | 需求上下文：图遍历取关联节点（代码/方案/意图/坑） |
| `get_project_info` | 读 | 项目枚举/画像查询（has_profile 占位标记 + hint 引导；scope_meta 回显 system 维度） |
| `list_requirements` | 读 | 需求清单枚举（分页+过滤；requirement_key 直查、fields 裁剪） |

## Dev 工具（8 个）

| 工具 | 读写 | 职责 |
|------|:---:|------|
| `submit_dev_artifacts` | 写 | 批量提交产物：CodeSnippet/Solution/DesignIntent/Pitfall + 产物间关系；传 requirement_id 四类产物按类型自动建边（implements/realized_by/embodies/described_by），省略则挂项目画像（游离知识）；宽松模式回执附 created/edges_created |
| `update_node` | 写 | 同 PM（限本角色可见节点） |
| `search_code_snippets` | 读 | 检索研发资产（代码/方案/意图/坑），按项目或 system 域隔离（system 维度检索全系统资产） |
| `search_similar_requirements` | 读 | 同 PM（dev 可用 system_id 定位可见需求再引用实现） |
| `analyze_impact_scope` / `get_requirement_context` | 读 | 同 PM |
| `get_project_info` / `list_requirements` | 读 | 同 PM |

## Admin 工具（20 个，另含全部 PM/Dev 工具）

| 工具 | 职责 |
|------|------|
| `review_pending_list` | 待审批队列（含超期/即将超期标记） |
| `review_batch_detail` | 批次详情：审批项 payload、冲突提示、target_id 回填 |
| `review_auto_process` | 自动审批：无冲突 auto_approved 直接入库，有冲突 needs_human_review 升级人工 |
| `review_approve` / `review_reject` | 人工审批通过（事务写入图谱）/ 退回（附原因） |
| `create_access_key` / `revoke_access_key` / `list_access_keys` / `update_access_key_scope` / `rotate_access_key` / `set_access_key_mode` | Access Key 的创建/吊销/列出/改范围/轮换/改审核模式（宽松开关） |
| `manage_system` | system 域管理：create/list/set_projects（全量覆盖）/add_projects/remove_projects（增量幂等）/bind_keys（授权 Key） |
| `manage_project_profile` | 项目画像直写（admin 豁免审批）；create 不传 project_id 自动生成 |
| `list_knowledge` | 知识节点枚举（按项目/类型/状态过滤） |
| `query_audit_log` | 审计日志多条件查询（项目/操作者/工具/时间） |
| `reindex_project_vectors` / `get_reindex_status` | 异步全量重嵌向量 / 任务进度轮询 |
| `get_graph_stats` | 图统计：节点/边按 type、system 维度聚合（AGE Cypher） |
| `get_graph_quality_report` | 图质量基线：孤儿节点数、重复度、连通分量数 |
| `generate_rule_edges` | 规则边生成：按节点属性规则批量建边（走审批批次） |

create/rotate Key 的返回带 `mcp_config`（给用户的客户端配置 JSON）与 `user_hint`（给用户的一句话接入提示，含角色技能文档的 GitHub 安装指引，不含 Key 明文）。

## 检索出参契约

`search_similar_requirements` / `search_code_snippets` 出参仅含 `fused`（融合精排结果，分数=向量余弦）与自诊字段：`query_terms`（全文引擎实际分词）、`candidates_total`（阈值过滤后、top_n 截断前的候选数）、`returned`（实际返回条数）、`truncated`（候选池是否大于 top_n）。`top_n` 默认 20；`min_score` 仅过滤纯向量命中（有全文命中的节点不受影响，None 关闭阈值）；`match_mode=any` 为宽召回。

## 典型协作工作流

```
admin                              pm                              dev
─────                              ──                              ───
manage_system create/set_projects
create_access_key ──────► 接入（pm key）
manage_project_profile create     publish_requirement ──┐
                                  （pending_review）     │
review_auto_process ◄──────────────────────────────────┘
（无冲突 auto_approved）              search_similar_requirements（消费）
                                   get_requirement_context
create_access_key ───────────────────────────────► 接入（dev key）
                                                            submit_dev_artifacts
                                                            （引用 requirement_id，
                                                             pending_review）
review_auto_process ◄──────────────────────────────────────┘
                                                            search_code_snippets
                                   analyze_impact_scope（影响面）
```

冲突场景：PM 重复发布相似需求 → `review_auto_process` 返回 needs_human_review + 冲突详情（相似度/匹配属性）→ admin 决策 `review_approve`（并存）或 `review_reject`。

## system 维度用法

1. **建域挂项目**：`manage_system(action="create", name=...)` → `set_projects(system_id, project_ids=[A,B])`；
2. **签发授权**：`bind_keys(system_id, key_ids/role_filter/grant_all)`——目标 Key 的 `scope.systems` 累积去重；
3. **发悬浮需求**：`publish_requirement(system_id=S)` 不带 project_id，需求跨项目存在；
4. **跨项目消费**：`search_similar_requirements(system_id=S)` 检索全系统需求（含悬浮）；dev 检索可见 system 的需求后引用实现，影响评估跨项目聚合。

## 宽松模式治理

- `set_access_key_mode(lax_mode=true, key_ids|role_filter)` 按 Key 开启：提交即自动处理（无冲突直入库，有冲突回审批队列）；
- `list_access_keys(lax_mode=true)` 查询宽松 Key；
- 全局熔断：`.env` 中 `LAX_MODE_ENABLED=false` 时所有宽松标记失效，强制走审批；
- 宽松提交的审计记录标记 `lax=true`（提交者即处理者），批次与审批模式同样落 `status=approved`。

## Skills 分发

首次接入按 create/rotate Key 返回的 `user_hint` 指引，从 GitHub raw URL 下载角色 SKILL.md（工具用法、参数模板、工作流指引）与放置说明。放置到 `.agents/skills/mem-lake-{role}/SKILL.md`（跨客户端通用路径）后重启 Agent 会话生效，一次安装后续会话自动加载。
