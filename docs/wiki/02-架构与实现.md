# 架构与实现

> 上一步：[项目定位与核心概念](01-项目定位与核心概念.md) · 下一步：[工具手册](03-工具手册.md)

## 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  上游：团队各角色的 AI Agent（PM/开发/管理者的 MCP 客户端）      │
│         Cursor / Claude Code / TRAE / 自研 Agent ...      │
└────────────────────────┬────────────────────────────────┘
                         │  MCP 协议（Streamable HTTP + X-MCP-Key）
┌────────────────────────▼────────────────────────────────┐
│  Mem Lake MCP 网关（容器 mem-lake :8000）                  │
│  认证 → RBAC → 限流 → 审计 → 24 工具 → 审批工作流           │
└───────┬───────────────────────────────────┬─────────────┘
        │ SQL（psycopg3 async）              │ HTTP
┌───────▼────────────────────┐  ┌───────────▼─────────────┐
│ PostgreSQL 17（容器 :5432）  │  │ Embedding 服务（:8001）   │
│ 节点表 + pgvector 向量       │  │ Qwen3-Embedding-0.6B    │
│ tsvector 中文全文            │  │ (1024 维) + rerank 精排  │
│ Apache AGE 图（关系边）       │  └─────────────────────────┘
└────────────────────────────┘
```

三容器单机部署（Docker Compose），启动顺序 postgres healthy → embedding healthy → mem-lake。

## 技术选型

| 选型 | 理由 |
|------|------|
| MCP 协议 + FastMCP 4.0 | 标准 Agent 接入协议，Streamable HTTP 传输；中间件钩子机制实现认证/鉴权/限流/审计 |
| PostgreSQL 17 单实例承载三种存储 | 一个数据库同时提供关系表（pgvector 向量 + tsvector 中文全文 + JSONB 属性）与属性图（Apache AGE 的 Cypher），事务内共写保证节点与边一致，免除多库同步 |
| zhparser 中文分词 | 中文全文检索的分词基础 |
| Qwen3-Embedding-0.6B（内置镜像，ModelScope 获取） | 本地推理无外部依赖；1024 维；指令感知（查询侧 prompt_name=query） |
| bge-reranker-base 精排（可选启用） | RRF 融合后的语义重排，提升 top 相关性 |
| bcrypt Access Key 认证 | 明文不落库；每次请求实时校验，Key 吊销/轮换即时生效 |
| Docker Compose | 三容器一键编排，本地化部署边界清晰 |

## 请求链路（一次工具调用）

`gateway/middleware.py` 四中间件按序执行：

1. **AccessKeyAuthMiddleware**（on_request）：提取 `X-MCP-Key` → 查库 bcrypt 认证 → 构造 AccessToken 写入 request scope；附带 MCP 协议版本校验；
2. **RBACMiddleware**（on_call_tool / on_list_tools）：按角色校验工具调用权；`tools/list` 按角色过滤，非本角色工具不可见；
3. **RateLimitMiddleware**（on_call_tool）：per-Key 令牌桶限流（默认 100 QPS），含桶内存治理（定期清扫 + 容量上限逐出）；
4. **AuditLogMiddleware**（on_call_tool）：记录调用审计（actor/tool/args/耗时/结果状态），Prometheus 指标同步上报。

工具层只做参数解析与事务边界，业务在 service 层，写入走审批工作流。

## 数据模型

| 表 | 职责 | 关键点 |
|----|------|--------|
| `knowledge_node` | 知识节点主表（真相源） | `project_id` 可空 + `system_id`（悬浮需求双归属）；`content_vector VECTOR(1024)`；tsvector 全文索引；组合索引 `(system_id,type,status)` |
| AGE 图（`mem_lake_graph`） | 节点投影 + 关系边 | 图节点只存 id/title/project_id/system_id；`MATCH ... CREATE` 写边，端点存在性由应用层显式校验（AGE MATCH 失败静默） |
| `approval_batch` / `approval_item` | 审批批次与审批项 | 三态 `pending_review → approved/rejected`；`operation_id` 幂等键；`target_id` 审批后回填真实节点 ID |
| `access_key` | 密钥 | bcrypt hash；`project_scope` 两级 dict `{systems,projects}`；`lax_mode` 宽松标记 |
| `system` / `system_project` | system 域与项目挂接 | name 唯一；复合主键映射，反查项目所属 system |
| `audit_log` | 审计 | append-only 只增不改；含 actor/action/target/detail/时间 |
| `reindex_task` | 异步向量任务 | `pending→running→done/failed` 状态机；`target_node_ids` 节点级嵌入；`project_id` 可空（悬浮需求） |

## 关键机制实现摘要

### 三引擎融合检索（`search/fusion.py`）
向量（pgvector 归一化内积，HNSW 索引）、全文（tsvector + zhparser）、图遍历（AGE）三路 **asyncio.gather 并行**执行，向量+全文结果 RRF 融合排序，图遍历结果独立返回。统一 `FilterSpec` 过滤契约编译到各引擎，保证隔离条件一致。可选 rerank 精排（`RERANK_TOP_K` 候选）。查询侧启用 embedding 指令感知（`prompt_name="query"`）。

### 三层冲突检测（`approval/conflict.py`）
审批前的查重：**L1 硬门控**（FilterSpec 限定项目/system + 类型 + approved）→ **L2 关键属性比对**（如 requirement_id 不同即不同实体，直接排除）→ **L3 内容语义相似度**（与落库同构的 embed 文本做向量比对，阈值 `CONFLICT_SIMILARITY_THRESHOLD` 默认 0.85，换模型用 `scripts/calibrate_conflict_threshold.py` 重标定）。三层全过才判冲突。悬浮需求按 system_id 收口候选域。

### 审批事务共写（`approval/service.py`）
审批通过时在同一事务内：写入 knowledge_node + AGE 图节点/边 + 冲突检测提示 + 状态流转 + target_id 回填，任一步失败整体回滚。向量生成延迟到后台（见下），审批调用不等 embedding。

### 异步向量补全（`gateway/background_tasks.py`）
审批/宽松入库后新建节点 `content_vector=NULL`，异步入队 `reindex_task`，后台 worker 批量向量化写回；任务状态落库可轮询（`get_reindex_status`）；启动期对账（孤儿任务复位）。入队失败不阻断写入，由全量重嵌兜底。

### 幂等与审计
`(submitted_by, batch_type, operation_id)` 唯一幂等，重复提交返回首次批次；审计日志 append-only，中间件层记录全部工具调用，service 层补充业务细节（含 system_id）。

## 源码结构

```
src/mem_lake/
├── gateway/        # MCP 网关：server（FastMCP 实例）、middleware、tools/（5 组工具）、background_tasks
├── approval/       # 审批工作流：service（状态机/事务共写）、conflict（三层冲突检测）、models
├── knowledge/      # 知识层：repository（节点 CRUD）、age_store（AGE 图）、schema（校验）、models、embed
├── search/         # 检索：vector / fulltext / graph / fusion（RRF）、filters（FilterSpec）、tag_expansion
├── auth/           # 认证鉴权：service（Key CRUD/认证）、rbac（角色工具集）、models
├── audit/          # 审计日志：service（append-only 写入/查询）
├── embedding/      # Embedding HTTP 客户端（独立容器调用方）
├── observability/  # Prometheus 指标 + structlog 结构化日志
├── db/             # 连接池/会话工厂、init（建表迁移）、base
├── skills/         # 三角色 SKILL.md（由 get_role_skills 分发）
├── cli/            # memlake-bootstrap-admin 引导 CLI
├── config.py       # 全量配置（pydantic-settings）
└── main.py         # uvicorn 入口
```

模块依赖单向：gateway → approval/search → knowledge → db，approval 与 search 严格隔离避免循环依赖。
