# 工具描述与角色 SKILL 文档优化计划

## 目标
让 PM/Dev/Admin 三类 Agent **按 SKILL.md 即可正确选工具、填对参数**；同步清理代码 docstring 中误导 Agent 的内容。范围仅限“描述文本与参数表对齐”，**不改任何业务逻辑/运行时行为**。

## 不做（过度设计，已剔除）
- CI 自动校验 SKILL↔代码参数一致性（低频改动 + 小团队，ROI 低）
- tool-call 评测 harness（需建评测框架，当前 SKILL 尚缺，先补齐）

## 任务清单
**P0 — 修正会直接导致调用失败的文档**
- P0-1 `pm/SKILL.md`：
  - `update_requirement_relations` 参数表改为 `relations:[{from_id,to_id,relation_type}]`（删 `requirement_id`/`supersedes`/`relates_to`/`conflicts_with` 扁平写法）
  - `publish_requirement` 改为嵌套 `requirement=` 结构，删除 `related.conflicts_with`
  - `submit_dev_artifacts` 改为嵌套 `artifacts=` 结构，补 Solution 必填 `version`
- P0-2 `admin/SKILL.md`：
  - `review_pending_list` 参数改为 `limit`/`offset`（删 `status`/`page`/`page_size`）
  - `manage_system` 补 `description` 参数

**P1 — 补齐缺失工具文档**
- P1-1 `pm/SKILL.md` / `dev/SKILL.md`：新增 §工具 覆盖全部缺失工具（参数表 + “何时用/何时不用”）：
  - pm：`update_node`、`search_similar_requirements`、`analyze_impact_scope`、`check_requirement_conflicts`、`get_project_profile`、`get_project_info`、`get_requirement_context`
  - dev：上述 + `search_code_snippets`
- P1-2 三份 SKILL 均补 `get_project_profile`、`get_requirement_context`；`get_project_info` 补 pm/dev 章节

**P2 — 描述提质（轻量）**
- P2-1 四个检索工具（`search_similar_requirements`/`search_code_snippets`/`get_requirement_context`/`analyze_impact_scope`）docstring + SKILL 各加一句“用我而非用 X”消歧
- P2-2 `review_approve`/`manage_project_profile` docstring 去除实现絮叨（“写 knowledge_node 表/AGE 图”等），改为面向 Agent 的行动语言
- P2-3 `get_requirement_context` 如实说明 `depth`/边类型当前为占位
- P2-4 三份 SKILL 顶部加“参数以工具签名为准”维护提示，防止再次手抄漂移
- P2-5 `manage_system` 改返回 Pydantic `Output` 模型（统一 24 工具风格，消除裸 dict 特例）

## 交付物
- 修改后的 3 份 `src/mem_lake/skills/{admin,pm,dev}/SKILL.md`
- 修改后的 `src/mem_lake/gateway/tools/*.py` 中 P2 涉及的 docstring/Field 描述 + `manage_tools.py` 的 `manage_system` 返回模型

## 验收（直接可用性标准）
1. 任一层 SKILL 参数表与代码签名逐一比对：**0 硬冲突**
2. 每个本角色工具在 SKILL 中有参数表 + 用途边界
3. 检索类工具有明确互斥说明
4. `manage_system` 返回结构与其它工具一致（结构化 Output）
5. 不新增任何 CI/评测/业务逻辑改动
