## 三、P1：上量前阻塞（阶段 2）

### FIX-01 数据库 schema 迁移机制

**定位**：db/init.py:28——`create_tables()` 仅 `create_all`，对已存在表整体跳过且启动无告警；v1.0.0 发行清理已删除 deploy 侧增量 SQL，存量库上的任何列/索引变更当前无生效通道。

**方案**：

1. 引入 Alembic（pyproject 增依赖并在 conda memlake 环境安装），`alembic init` 采用 async 模板，迁移目录定为 `alembic/`。
2. `env.py` 挂接项目配置：引擎复用 `db/session.py` 的连接配置，`target_metadata` 指向 `Base.metadata`（import 各模块 models 触发注册，与 create_tables 同一方式）。
3. 以 `9013b07` 的 models 生成 `0001_initial` 基线（对空库 autogenerate，人工核对后入库）。
4. 存量库处理：执行 `alembic stamp head` 完成登记。
5. 启动校验：应用启动流程（init_database 之后）比对 `alembic_version` 表与脚本目录 heads，不一致抛 `RuntimeError` 并指明处置命令（升级 / stamp）。
6. 过渡约定：v1.0.x 内的小型 schema 变更继续按项目既有约定在 `create_tables()` 内写幂等 ALTER，同时登记等价 Alembic revision，两者保持一致；v1.1 起新增变更仅走 Alembic。

**验证**：空库场景 `alembic upgrade head` 后应用启动校验通过且 autogenerate 产出空 diff；存量库 stamp 后启动校验通过。

### FIX-02 DEALLOCATE 掩盖原始异常

**定位**：age_store.py:102-103——`finally` 中执行 DEALLOCATE。Cypher 执行失败后 PG 事务进入 aborted 状态（25P02），finally 中的 DEALLOCATE 必抛 `InFailedSqlTransaction` 并替换真正的 Cypher 错误。

**方案**：

1. `age_store.py` 引入模块 logger（`logging.getLogger("mem_lake.knowledge.age_store")`）。
2. `_exec_cypher` 参数化路径重构：EXECUTE 成功后 DEALLOCATE 在成功分支顺序执行；EXECUTE 抛异常路径保留原始异常向上传播，清理动作改为 except 分支内 best-effort（捕获次级异常仅 `logger.warning`）。
3. prepared statement 在异常路径下的少量泄漏由连接池连接回收兜底（DEALLOCATE 为会话级，连接归还即释放）。

**验证**：tests/integration/test_age_graph_store.py 新增用例——构造必然失败的 Cypher，断言抛出异常的 message 为原始 Cypher 错误且不含 `InFailedSqlTransaction`。

### FIX-03 RLS 文档脱节

**定位**：repository.py:12（模块 docstring 引用不存在的 `auth/rls.py`）；filters.py:27（宣称「RLS 已强制，此处冗余校验」）；db/init.py:16-17 注释为准确的设计说明（保留）。

**方案**：

1. `rg -n "RLS" src/` 全量清点，逐处修正表述；至少覆盖上述两处错误声明。
2. 统一口径：项目隔离唯一机制 = 应用层 `validate_project_access` + 检索侧 `FilterSpec`。
3. `FilterSpec` docstring 显式声明：`project_id=None` 表示该维度不过滤（悬浮需求的冲突检测依赖此语义），新增检索接口必须显式传入 filters。

**验证**：`rg -n "RLS" src/` 输出仅剩 db/init.py 的设计说明；相关测试通过。

### FIX-04 向量索引 opclass 统一

**定位**：models.py:161-167（`idx_node_vector`）与 208-214（`idx_node_embedding_vector`）期望 `vector_ip_ops`；部署库实际为 `vector_cosine_ops`（create_all 跳过已存在索引所致）。cosine_ops 索引不服务 `<#>`（max_inner_product）查询，部署库向量检索实际走顺序扫描。该项是 FIX-01 的现实病例佐证。

**方案**：作为 FIX-01 之后的 Alembic revision `0002_fix_vector_index_opclass`：DROP 两个索引并以 `vector_ip_ops`（参数 m=32、ef_construction=400 保持）重建；部署库执行该迁移。

**验证**：`pg_indexes` 查询确认两索引 opclass 为 `vector_ip_ops`；`EXPLAIN` 向量检索确认走 Index Scan；集成存量失败 `test_indexes_exist` 转为通过（基线更新为 260 passed + 1 存量失败）。

**验证**：单测模拟两处并发认领同一 task，仅一方进入执行体。
